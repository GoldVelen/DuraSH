# Agent Note: Host 持有的可靠性闭环与派生会话状态

Status: implemented

[English](2026-08-31-host-owned-reliability-loop.md) | 中文

## 问题

DuraSH 的第一个可靠性切片让面向模型的工具等待完整实施-审查-返工闭环。调用跨过代码运行的 600000 ms wall-clock 上限后会继承 abort 信号，取消仍在运行的闭环，并在实际记录中六次产生虚假的 `cancelled`。Host 与 Agent 拆卸也使用同一取消路径，因此进程生命周期同样可能被记录成用户意图。浏览器只有策略开关，没有持久阶段状态；保存的思考强度也停留在策略行，没有到达 workflow 子代理。provider、stream、worker 与上下文故障因此需要一套统一隔离设计，而不是更大的超时或另一份旧 3081 执行器。

## 决策

版本 2 可靠性闭环在快速持久交接后归 Host 所有。

- `startDetached()` 鉴权精确的存活根 Agent，以 `accepted` 写入版本 2 记录，取得唯一驱动者，发布状态，并在阶段结算前返回带 revision 的接管回执。工具不等待驱动者，也不把自身 abort 信号订阅到取消。
- `reliability_loop` domain 记录是唯一执行真源。它拥有会话标识、revision、完整不可变通道、两轮报告、阶段与生命周期时间。预发布的版本 1 介质会被拒绝，不重写，也不推断。
- `reliability-loop/change` 是 domain 写入后派生的完整 log-only 会话投影。它支持可重连状态与一次终态 Conversation Node，但绝不推进执行。Agent 接管会根据 domain 修补缺失投影。
- 用户取消与 Host 暂停是不同操作。受鉴权的取消会等待 worker 和子代理静止，写入一次 `cancelled` 终态。Agent 或服务拆卸会暂停活动 run，保留非终态阶段，让后续 Agent 接管只重跑第一个未完成阶段。
- 每个驱动者都在开始推进前挂接结果观察者。子代理、provider、workflow worker、报告与存储故障被收敛；只要记录仍可写，它们就让该闭环进入 `failed`，不会终止 Web Host。
- 策略使用实时精确模型能力元数据，以校验错误保留无效既有值，绝不静默改档。面板读取并行解析目录；交接前只重新校验两条已选路由，避免无关目录延迟持久接管。通用 workflow worker 通过带类型协议把 `reasoningEffort` 送入子代理 `AgentOptions`。
- 阶段子代理加入父代理的精确 preset generation。token 计量、可回放工具结果裁剪与压缩继续是通用 preset 能力；不恢复 workflow 专用超时、溢出引擎或旧 3081 执行器。

浏览器在 composer 上方注册 order `-10` 的紧凑状态条。它只渲染当前会话，覆盖全部阶段，按需加载按会话鉴权的详情，二次确认取消，只关闭一个精确终态 revision。详情读取返回最新归属记录，不把 revision 当作写入门禁，因此稳定的 loop-id 终态节点在状态条关闭后仍可使用。该节点只渲染一次，不再调用模型，也不把实时遥测塞进主对话。

## 已考虑的替代方案

- **提高或移除 600000 ms 代码运行上限。** 拒绝，因为这会保留错误所有者：回合结束、浏览器断开或后续任何外层取消仍能控制持久工作流。交接必须在上限前结束，而不是改写上限。
- **让会话事件成为执行存储。** 拒绝，因为这会创建第二套状态机，或让控制恢复依赖模型历史存储。domain 记录保持权威；会话事件明确只是可替换展示状态。
- **由浏览器轮询状态 Remote。** 拒绝，因为更新会受连接生命周期支配，也无法提供可重放的每闭环一次终态结果。完整事件已经符合会话刷新与重连行为。
- **恢复旧 3081 workflow 执行器或为 Grok 写特殊判断。** 拒绝，因为两者都会复制策略。当前 preset 组合已经拥有上下文韧性，adapter 元数据已经拥有精确模型档位能力。

## 后果

成功交接不再占用外层工具的长运行区间。Host 拆卸不再伪装成用户取消，workflow 故障也只影响一条持久闭环。刷新与重启可以从持久事实重建状态条与终态结果。代价是预发布期间明确的版本 2 磁盘格式断点、必须与 SDK 消费方同步的派生会话事件，以及阶段级恢复粒度：通用 workflow 引擎不记录脚本内部进度，因此崩溃仍会重跑第一个未完成阶段。

当前产品仍是一个实施者、一个独立审查者和最多一轮返工。计划协调、多路审查汇总、成员级持久进度与自动成本调度不属于本决策。

## 测试

聚焦测试固定快速回执、包含终态写入/索引竞争的重复启动所有权、两轮报告、显式取消、暂停与接管、终态去重、stale 写入与跨会话读取、状态条关闭后的持久终态详情、投影 revision 回退拒绝、存储与子代理失败隔离、交接只校验已选路由、workflow `reasoningEffort` 传递、精确模型策略漂移、Grok 4.6 的 low/medium/high/xhigh 能力、全部状态阶段、slot 顺序、只接受终态的 Conversation Node，以及 standard preset 对 token meter、工具结果裁剪与压缩的继承。

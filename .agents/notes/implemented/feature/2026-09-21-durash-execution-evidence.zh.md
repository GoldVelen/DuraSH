# Agent Note: DuraSH 执行证据与验收

Status: implemented

[English](2026-09-21-durash-execution-evidence.md) | 中文

## 问题

审查者可能批准一份可信的摘要，却没有发现测试属于旧候选、skip 缺少前置，或定向结果掩盖了必需整包失败。把每段直接对话都交给独立模型会增加成本，却不能确立这些可执行核对的事实。

## 决策

现有可靠性运行时拥有独立的验收 domain，供直接工具和工作流阶段共用。执行收据在命令开始前绑定限定范围的源码字节，并独立于模型陈述保存结果。用户结果要求保持固定；执行计划调整保留原因，并使受影响证据失效。独立审查判断语义充分性，包括具有风险的测试变化。已有的一轮返工上限保持不变。

## 考虑过的替代方案

自然语言完成检测不能确立源码、产物或目标身份。静态测试变化匹配不能决定替换失效测试是否保留用户结果。第二套编排系统会重复工作流引擎已有的所有权。

## 后果

直接聊天获得宿主可见的检查状态，不产生第二次模型调用。绑定任务的工作流要求同一候选同时具有程序证据与独立审批。范围选择、测试充分性和设备可见结果仍需相应观察及语义审查；适配器不可用时保持未核验。支持的适配器和限制见[运行时参考](../../../../packages/reliability/durash-reliability-loop/README.zh.md#task-acceptance-evidence)。

## 测试

包内测试覆盖陈旧源码及构建、必需整包失败、skip 证据、目标不匹配、输入不变时的复用、持久化与取消。无需密钥的 `durash-acceptance` 会话 fixture 使用随附 headless profile 及产品插件、真实 Git 和 shell 命令，以及受控模型录制。UI 测试在工作流关闭时区分检查与独立审查。

回归用例复现了 invariant companion 拒绝生产 driver 正常第二轮完成状态的问题。接受条件现与实际写入者一致；实施与审查轮次不匹配仍被拒绝。显式声明的 ignored 文件输入会参与散列，缺失输入路径不会因其他路径有效而被忽略。
